# Key Flow CRM API

Laravel 12 REST API for the Key Flow real estate CRM.

## Prerequisites

| Tool | Version | Notes |
|---|---|---|
| PHP | 8.2+ (8.4 recommended) | Extensions: `pdo_mysql`, `mbstring`, `gd`, `zip`, `bcmath`, `curl`, `intl` |
| Composer | 2.x | |
| MySQL | 8.x | MariaDB also works |
| Node.js | 20+ | Only needed to build the Vite assets |
| FFmpeg | any recent | Needed for video processing. Install it with `brew install ffmpeg` or `apt install ffmpeg` |

## Setup

### 1. Install dependencies

```bash
composer install
npm install
```

### 2. Create your `.env`

The template is `.env.sample`. Note that `composer setup` looks for `.env.example`, which doesn't exist, so copy the file manually:

```bash
cp .env.sample .env
```

Fill in the values described in [Environment variables](#environment-variables) below **before** you run anything else.

### 3. Generate keys

```bash
php artisan key:generate          # sets APP_KEY
php artisan jwt:secret            # sets JWT_SECRET (API login won't work without it)
php artisan webpush:vapid-keys    # optional: sets the VAPID_* keys for browser push
```

### 4. Create the database and seed it

Create an empty MySQL database that matches `DB_DATABASE`, then run:

```bash
php artisan migrate
php artisan db:seed
php artisan storage:link
```

The seeders create the roles, permissions, global settings, email templates, portal settings, locations, teams and a super admin:

- **Email:** `admin@gmail.com`
- **Password:** `12345678`

Change this password on any shared environment.

### 5. Run the app

```bash
composer dev
```

This starts the API server (`http://localhost:8000`), a queue listener, the log viewer (`pail`) and Vite, all together.

Start these separately when you need them:

```bash
php artisan reverb:start      # WebSocket server for real-time notifications
php artisan schedule:work     # scheduled jobs (see the warning below)
```

> ⚠️ **Be careful with the scheduler locally.** Scheduled commands send emails and WhatsApp messages, push to Property Finder and Bayut, and import portal leads. Only run `schedule:work` locally with the external services switched off (see [Safe local defaults](#safe-local-defaults)).

In production, the queue worker, Reverb and the scheduler run under PM2. See `ecosystem.config.cjs`.

## Environment variables

`.env.sample` lists every key with a comment. The tables below explain what each group is for and what you actually need.

### Required to boot the app

| Variable | What to set |
|---|---|
| `APP_NAME`, `APP_ENV`, `APP_DEBUG` | `APP_ENV=local` and `APP_DEBUG=true` for development |
| `APP_KEY` | Generated by `php artisan key:generate` |
| `APP_URL` | URL of this API, e.g. `http://localhost:8000` |
| `FRONTEND_URL` | URL of the CRM frontend, e.g. `http://localhost:3000`. It's used in email and notification links. |
| `DB_CONNECTION`, `DB_HOST`, `DB_PORT`, `DB_DATABASE`, `DB_USERNAME`, `DB_PASSWORD` | Your **local** MySQL database |
| `JWT_SECRET`, `JWT_ALGO` | Generated by `php artisan jwt:secret`. Keep `JWT_ALGO=HS256`. |
| `SESSION_DRIVER`, `CACHE_STORE`, `QUEUE_CONNECTION` | Leave these as `database` (the tables are created by the migrations) |
| `FILESYSTEM_DISK` | `local` for development |
| `LOG_CHANNEL`, `LOG_STACK`, `LOG_LEVEL` | The defaults are fine. `LOG_DAILY_DAYS` (optional) sets how many days of daily logs to keep. |
| `API_LOG_USERNAME`, `API_LOG_PASSWORD` | Basic-auth login for the API log viewer. Change these from the defaults. |

> 🚨 **Never point `DB_*` at the AWS RDS host `crm-staging-db…rds.amazonaws.com`.** Despite its name, it is the **live production** database. Any migration, seed or tinker command against it changes real client data.

### File storage (AWS S3)

Uploads such as listing photos, documents and avatars go to two S3 buckets.

| Variable | What to set |
|---|---|
| `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY` | IAM credentials with access to both buckets |
| `AWS_DEFAULT_REGION` | `ap-south-1` |
| `AWS_PUBLIC_BUCKET` | Bucket for publicly served files |
| `AWS_PRIVATE_BUCKET` | Bucket for private files, served via pre-signed URLs |
| `AWS_PUBLIC_URL` | Optional CloudFront/CDN domain for the public bucket |
| `S3_SIGNED_URL_TTL` | How long a pre-signed URL stays valid, in minutes (default `10`) |

Ask the team lead for development bucket credentials. Without them, uploads fail.

### Email

| Variable | What to set |
|---|---|
| `MAIL_MAILER` | Use `log` locally so emails are written to `storage/logs` instead of sent. Use `smtp` in production. |
| `MAIL_HOST`, `MAIL_PORT`, `MAIL_USERNAME`, `MAIL_PASSWORD`, `MAIL_ENCRYPTION`, `MAIL_SCHEME` | SMTP server details (only needed when `MAIL_MAILER=smtp`) |
| `MAIL_FROM_ADDRESS`, `MAIL_FROM_NAME` | Sender shown on outgoing emails |

### Real-time notifications (Reverb)

| Variable | What to set |
|---|---|
| `BROADCAST_CONNECTION` | `reverb` (use `log` if you aren't running Reverb) |
| `REVERB_APP_ID`, `REVERB_APP_KEY`, `REVERB_APP_SECRET` | Any values locally. The frontend must use the same key. |
| `REVERB_HOST`, `REVERB_PORT`, `REVERB_SCHEME` | Where the WebSocket server listens, e.g. `localhost`, `8080`, `http` |
| `VITE_REVERB_APP_KEY`, `VITE_REVERB_HOST`, `VITE_REVERB_PORT`, `VITE_REVERB_SCHEME` | Copies of the `REVERB_*` values for the Vite build |
| `PUSHER_*` | Not used. Leave them blank. |

### Browser push notifications

| Variable | What to set |
|---|---|
| `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY` | Generated by `php artisan webpush:vapid-keys` |
| `VAPID_SUBJECT` | A `mailto:` address or site URL that identifies the sender |

### Property portals (Property Finder and Bayut)

These are needed for publishing listings to the portals and importing leads from them.

| Variable | What to set |
|---|---|
| `PROPERTY_FINDER_API_URL`, `PROPERTY_FINDER_AUTH_URL` | Keep the defaults from `.env.sample` |
| `PROPERTY_FINDER_API_KEY`, `PROPERTY_FINDER_API_SECRET` | Property Finder API credentials |
| `PROPERTY_FINDER_DEFAULT_PUBLIC_PROFILE_ID` | Profile used when an agent has no Property Finder profile of their own |
| `PROPERTY_FINDER_WEBHOOK_CALLBACK_URL`, `PROPERTY_FINDER_WEBHOOK_LEAD_CALLBACK_URL` | Public URLs Property Finder calls back for listing events and new leads |
| `PROPERTY_FINDER_WEBHOOK_SECRET`, `PROPERTY_FINDER_WEBHOOK_EVENTS` | Webhook signing secret and the events to subscribe to |
| `CRM_DEFAULT_AGENT_ID` | User ID that portal leads are assigned to when no agent matches |
| `BAYUT_API_URL`, `BAYUT_API_TOKEN` | Bayut API URL and token |

> Leave the portal credentials **blank locally** unless you are deliberately testing against the portals. They point at the client's live portal accounts.

### WhatsApp (360dialog)

| Variable | What to set |
|---|---|
| `WHATSAPP_360_ENABLED` | **Set to `false` locally.** It defaults to `true` when the key is missing. |
| `WHATSAPP_360_ENDPOINT`, `WHATSAPP_360_TOKEN`, `WHATSAPP_360_SENDER`, `WHATSAPP_360_LANGUAGE` | API endpoint, token, sender number and template language |
| `WHATSAPP_360_WEBHOOK_SECRET` | Secret for verifying incoming WhatsApp webhooks |
| `WHATSAPP_360_TEMPLATE_*` | Optional overrides for template names. The defaults are in `config/services.php`. |

### Other integrations (optional)

| Variable | Used for |
|---|---|
| `AZURE_CLIENT_ID`, `AZURE_CLIENT_SECRET`, `AZURE_TENANT_ID`, `AZURE_REDIRECT_URI` | Outlook calendar sync through Microsoft OAuth |
| `SALESFORCE_CLIENT_ID`, `SALESFORCE_CLIENT_SECRET`, `SALESFORCE_LOGIN_URL`, `SALESFORCE_USERNAME`, `SALESFORCE_PASSWORD` | Salesforce data import commands |
| `OPENAI_API_KEY`, `OPENAI_API_URL`, `OPENAI_MODEL` | AI-generated text (model defaults to `gpt-4o-mini`) |
| `GOOGLE_MAPS_STATIC_KEY` | Static map images |
| `FFMPEG_BINARIES`, `FFPROBE_BINARIES` | Paths to `ffmpeg` and `ffprobe`. On macOS with Homebrew these are `/opt/homebrew/bin/ffmpeg` and `/opt/homebrew/bin/ffprobe`. |

### Mobile app version enforcement

| Variable | What to set |
|---|---|
| `IOS_APP_REQUIRED_VERSION`, `ANDROID_APP_REQUIRED_VERSION` | Current app versions. Leave them blank to turn the check off. |
| `MIN_IOS_APP_REQUIRED_VERSION`, `MIN_ANDROID_APP_REQUIRED_VERSION` | Older versions that are still allowed, flagged with `partialUpdate=true` |
| `APP_REQUIRED_APP_VERSION` | Legacy header check. It is being removed. |

The mobile apps send `X-App-Platform`, `X-App-Version` and `X-App-Build` headers. A client that doesn't match the versions above gets a `426` response and is told to update.

### Safe local defaults

Use these locally so your machine never contacts real clients or the live portals:

```dotenv
APP_ENV=local
DB_HOST=127.0.0.1            # never the RDS production host
MAIL_MAILER=log
WHATSAPP_360_ENABLED=false
BROADCAST_CONNECTION=log     # or reverb if you are running it
PROPERTY_FINDER_API_KEY=
PROPERTY_FINDER_API_SECRET=
BAYUT_API_TOKEN=
```

### Timezone

`config/app.php` keeps the app on `UTC`, so timestamps are stored in UTC. The business timezone used for reports, reminders and the scheduler is the `_timeZone` global setting, seeded by `GlobalSettingSeeder` and editable in the admin settings. It does not come from `.env`.

## Running tests

```bash
composer test
```

Tests use an in-memory SQLite database with mail, queue and cache faked (see `phpunit.xml`), so they never touch your `.env` database.

```bash
# Check formatting without fixing (dry run)
composer lint:check
```
